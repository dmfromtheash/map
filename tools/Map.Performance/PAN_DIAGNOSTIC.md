# Проверка pan100 и portable

У `native-million-assets` переменная `MAP_PERF_PAN100_ONLY=1` выбирает fit,
подготовленный25%, переход100%безожидания, pan120 и затем подготовленныйpan600.
Значение `legacy` повторяет префикс обычного маршрута: fit→25%→pan25/capture→100%→pan100,
затем добавляет длиннуюpan600. Остальные действия в этом режиме не проверяются.

`MAP_PERF_PORTABLE_FIXTURE=plain|portable` импортирует100SHA в изолированный профиль.
Portable строится явно ДО измерения открытия; обычный reader библиотеку не пишет.
Каждый запуск имеет пустой машинный кэш, но импорт прогревает файловый кэш Windows.
Порядок сравнения A–B–B–A; каждый запуск и разброс публикуются отдельно.

`runtimeDuringRoute` содержит дельты JitInfo, CPU процесса, GetProcessIoCounters,
GC/выделений, worker-чтений и Brotli, принятия готовых изображений, GPU flush,
camera reuse и фактических интервалов подачи ввода. Счётчики процесса/JIT включают
фоновые потоки; это не длительность работы render thread. `readsOnCanvasThread`
отмечает инструментированные операции Store на последнем потоке BeginFrame,
а не все файловые операции приложения. Значения берутся до ожидания settled.

ЖИВОЙ результат относится к окну/холсту/GPU completion, не к scan-out монитора.
Проверять окончательные GPU PNG и снимки окна, удалять профиль после каждого запуска.
