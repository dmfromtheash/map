# Map.Performance

Локальный deterministic runner Stage 13. Проект намеренно не входит в `Map.slnx` и не запускается
обычной сборкой приложения. Generated JSON записывается в ignored `tmp/performance` либо в явно
переданный `--output`.

```powershell
dotnet run --project .\tools\Map.Performance\Map.Performance.csproj -c Release -- `
  --profile stage13a --object-count 50000 --seed 13013 --warmup 1 --iterations 5
```

Доступные профили текущего среза: `stage13a`, `stage13b-baseline`, `stage13b`,
`stage13c-baseline`, `stage13c`, `stage13d`, `small-render`, `hit-test`, `marquee`,
`object-tree`, `spatial-query` и соответствующие `native-stage13a`…`native-stage13d`.
Перед/после сравниваются с одинаковыми `seed`, `object-count` и fixture hash. CPU-render timing
не выдаётся за native input-to-present: native-профиль открывает отдельное настоящее off-screen
окно без активации и системного ввода, считает реализованные строки и измеряет путь от
interaction-start до завершения Skia scene pass. `stage13d` дополнительно проверяет 131K sparse
canvas, bounded export plan, 50K/100K save-reopen и test-only 262K boundary; 262K не меняет
production policy.

## Адресная проверка Stage 18

Текущий сценарий композиции: `MAP_STAGE18_NATURAL_CHECK=1` и
`MAP_STAGE18_DENSITY_ASSET=<существующий PNG гор>`, затем
`--profile native-stage18 --output artifacts/area-selection-check/final-structure.json`.
Он использует выбранную копию PNG только для чтения, собственное starter-tree и отдельные
карты/каталог/профиль. Проверяет четыре рисунка, точное число в черновике, размещение,
плотность 0/20/50/80/100, стабильность прежних объектов, seed, размеры/ноль, частичное смыкание
с защитой силуэта, порядок глубины, ручное выделение/перенос/удаление, исключения и save/reopen.
Дополнительная диагональная область показывает тот же расчёт гряды в форме, близкой к
присланному владельцем примеру. `MAP_STAGE18_SMALL_MEMORY=1` ограничивает доступную редактору
RAM сверху 1 GiB; это функциональная проверка допуска, не измерение общего RAM/GPU peak.

Report сохраняет полное окно и отдельный `.canvas.png` настоящего Canvas для сравнения с
референсами. `MaximumTreeOverlapFraction` — пересечение AABB, а не непрозрачных пикселей:
при силуэтах оно может превышать 55%. `CountOverlaps` проверяет фактическое правило текущего
layout: попарное покрытие силуэта/верхушки, либо консервативный fallback с эффектами/без маски.
`GatePassed` относится к перечисленным функциональным проверкам. Он **не подтверждает**,
что владелец одобрил рисунок или что он визуально повторяет референс. После прогона нужно
открыть PNG и сопоставить связность, иерархию размеров, форму просветов и заметность рядов.

`MAP_STAGE18_LOCAL_MEASUREMENT_ONLY=1` с `MAP_STAGE18_FIXTURE=<исходная карта порядка 20K>`
выполняет только запрошенный контрактом один замер локального угла, не повторяя уже зелёный
сценарий композиции. Он создаёт `stage18-native/ordinary-map-copy.mapproj` с `overwrite:false`;
требуется отсутствие именно этой копии в выбранном выходе. Измеритель явно выбирает собственное
starter-tree, добавляет слой только в копию, до таймера находит непустую правку и проверяет
ссылки всех исходных объектов, shared cells, Undo/Redo и SHA исходника. Gate этого режима —
фактический замер и его семь проверок; это не замена visual smoke или полного native сценария.

Сборка инструмента выполняется отдельно после Release `Map.slnx`; можно использовать
`-p:BuildProjectReferences=false` с тем же выходом сборки. Не запускать одновременно с
экспортными проверками при недостатке свободной памяти. Ниже сохранены дополнительные
ранние сценарии; их результаты нельзя выдавать за свежий visual/performance baseline.

`--profile native-stage18 --output artifacts/stage18-check/native.json` проверяет создание вогнутой
области, локальную границу/плотность, отделение, Undo/Redo, сохранение, reopen с пустым
каталогом, текущую карточку, bake/delete и PNG. `MAP_STAGE18_FIXTURE` указывает существующий
`.mapproj` порядка 20 тысяч объектов: измеритель создаёт временную копию и проверяет SHA
оригинала. Собственное окно `ShowActivated=false`, без системного ввода; все изменяемые пути
изолированы. Report разделяет scoped events, adapter calls, время до кадра, private bytes,
allocated UI bytes, retained heap с историей/индексами/кадром и число затронутых/разделённых ячеек.
Это отдельный адресный прогон по запросу, не часть обычного build или полного suite.
После изменения только панели можно указать `MAP_STAGE18_UI_ONLY=1` и `MAP_STAGE18_UI_FIXTURE`
с уже проверенным проектом области: отдельный короткий сценарий проверяет подпись плотности,
изменение параметров, карточку сохранённого ассета, отмену/повторный выбор и сохранение либо
корректный отказ по реальному допуску памяти. Report явно называет исход сохранения; полный
сценарий и успешный замер большой карты не повторяются. Полный сценарий копирования требует
свежую папку своей копии; короткие исправления переиспользуют проверочный выход в `artifacts/`.
Fixture не перезаписывается.

`MAP_STAGE18_SELECTION_CHECK=1` вместе с `MAP_STAGE18_DENSITY_ASSET=<существующий PNG>` запускает
короткий сценарий композиции и ручного выделения: сравнение сохранённой v2 с текущей v4, явная кнопка перехода,
маркировка рамкой, клик без изменения, перенос группы, кнопка удаления, Undo/Redo и save/reopen
с ручными исключениями после изменения плотности. Окно, каталог, карта и профиль изолированы;
большая карта, замер памяти и PNG viewer в этом сценарии не запускаются. Report содержит числа
объектов до/после уплотнения и число выбранных штампов, а не новый общий performance baseline.

Расстановка Stage 18 учитывает размеры изображений. Полный профиль проверяет нулевое число
конфликтующих пар по сохранённому правилу layout; допустимое смыкание не является конфликтом.
UI-профиль на раннем проекте также нажимает «Расположить естественно» и проверяет точный
Undo/Redo. Для замера
на заполненной карте создаётся отдельный пустой объектный слой только в её временной копии:
исходные 20 тысяч объектов сохраняются. Непустая локальная правка границы выбирается по геометрии
до запуска таймера, без пробных правок; её конечная X-координата записывается в report.
