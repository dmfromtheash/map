# Живая матрица функций и стилей

Профиль `native-million-assets` открывает настоящее окно редактора и холст.
Дополнительные маршруты включаются только переменными окружения:

```powershell
$env:MAP_DRIVE_LIBRARY_ROOTS='D:\MapLibrary'
$env:MAP_MEASURE_GPU_FLUSH='1'
$env:MAP_MILLION_CASE='giant' # standard, giant, hex, light, style
$env:MAP_MILLION_STYLE='WatercolorBigShapes' # off или точное имя MapStylePreset
$env:MAP_MILLION_FUNCTIONS='navigation,terrain,water-road,placement,layout,selection,style-light,export'
$env:MAP_MILLION_STEPS='600'
$env:MAP_MILLION_CACHE='warm' # reset-render: сброс только кэшей отрисовки
dotnet run --project tools/Map.Performance -c Release --no-build -- --profile native-million-assets --object-count 1000000 --output C:\Checks\matrix.json
```

`hex` требует `MAP_MILLION_CASE=hex`; `all` включает его тоже. Количество шагов120–6000,
по умолчанию600. Короткий120-шаговый запуск проверяет инструмент, не заменяет приёмку
миллиона. Без переменных функций/стиля остаётся прежний маршрут native-million-assets.

Сцена матрицы содержит исходное количество штампов, сушу на62%ширины с пропуском
каждой17-й плитки, реку и дорогу. Одинаковые байты покрытия земли разделяются между
плитками: это проверка большой площади, а не16ГиБ уникальных нарисованных данных.

Маршруты: панорама/колесо, кисти земли/материала/скал/рельефа/маски, река/озеро/дорога,
расстановка/серия, раскладка пути/области, выделение/перенос/поворот/размер/текст,
стиль/свет, гексы, предпросмотр экспорта. Изменения проверяются через Undo/Redo и
сравнение затронутого состояния документа. Ввод идёт через штатный canvas/router и
публичные команды редактора; это не проверка аппаратного ввода мыши/мониторного scan-out.

Отчёт различает время работы кадра, интервалы кадров и ввод→кадр; сохраняет1%low,
p95/p99/max, число пауз, подготовку после жеста и кадры setup/reset. Счётчик всех кадров
охватывает также уточнение и экспортный preview. Снимки окна и GPU сохраняются вместе;
их нужно просмотреть и сравнить окончательные пиксели. Функциональное прохождение
маршрута не означает прохождение порогов FPS. Все стили enum и ручные сценарии
(массовое выделение, реальные диалоги/горячие клавиши) требуют отдельных строк приёмки.

## Лестница постройки (`native-build-ladder`)

Владелец 2026-11-16: живой прогон не набрасывает кучу ассетов, а строит карту по очереди, как человек:
то континенты, то комнаты; каждый прогон разный по виду; холодный и горячий. Окно редактора на экране
ноутбука (как `native-million-assets`); каждая правка — команда редактора (жесты холста через штатный
router или кнопки панели), всё в истории Undo.

Фазы: `continents` (эллипсы и многоугольники «Земли», неровный берег кистью, заливы стиранием, острова,
материал земли, стиль моря) → `rivers` («Река отсюда в море», озёра) → `relief` (рельеф «Поднять» по
хребтам, горы «Серией», холмы «Путём», лес «Областью», «Россыпь» до доли фазы) → `roads` («Проложить
дорогу A→B» между городами, подпись вдоль дороги) → `towns` (замок «По одному», дома «Россыпью», имя;
у первого города интерьер в 100 %: коридор и комнаты, двери, мебель) → `regions` (области с правилами
«только суша / не на воду / не на дорогу» и подписью области, подписи рек вдоль русла, страны и моря,
роза ветров, линейка, картуш, легенда) → `fill` («Россыпь» до `--object-count`). Доли объектов: 35 % к
концу relief, 50 % towns, 60 % regions, 100 % fill. Сторона холста: ≤50 000 → 16 384, ≤500 000 → 32 768,
≤1 000 000 → 65 536, больше → 131 072 (`MAP_BUILD_SIDE` переопределяет).

Seed: `--seed`, иначе `MAP_BUILD_SEED`, иначе часы; пишется в отчёт (`environment.seed`). Тот же seed —
та же карта (раскладка, порядок, наборы библиотеки). Библиотека: `MAP_DRIVE_LIBRARY_ROOTS`; каталоги —
`MAP_PERF_CATALOGS` или сам профиль берёт fantasy-world, fantasy-regional, parchment-world*, modern-interiors-1.

После каждой фазы: таблица правок (`buildPhases[].edits`: число, отказы, добавлено объектов, работа UI p50/p95/max,
команда→кадр p95; ожидание подготовки ассетов отдельной строкой `asset-prepare`) и маршруты как в FPS-сетке:
`fit` (время до резкости), `pan/fit`, `wheel/in-100`, `pan/100`, `wheel/in-400`, `pan/400`, `wheel/out-fit`,
`pan/edge-to-edge-100`; рабочий набор памяти; снимки `<фаза>-fit` и `<фаза>-100` (`towns` ещё `-400`).
В конце карта сохраняется штатным «Сохранить как» (атомарно) в `MAP_BUILD_SAVE` или рядом с отчётом.
`MAP_BUILD_OPEN=<карта>` — второй процесс: открытие сохранённой карты (inspect → редактор), время до
резкого вида целиком (`scenarios[reopen].openToExactTerrainMs`) и те же маршруты, пока не прошло 60 с.

Запуск лестницы (ПК и USER, из своей копии репозитория; сначала Release-сборка `tools/Map.Performance`):

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\ai\remote\Run-BuildLadder.ps1 -Tree C:\Projects\Map -Mode Both
# USER: -Library D:\MapLibrary ; одна ступень: -Counts 10000 ; повтор карты: -Seed 12345
```

`-Mode Cold` — пустой локальный derived перед постройкой и перед повторным открытием; `Warm` — кеш
сохраняется; `Both` — сначала холодный, потом тёплый с тем же seed. Строки в `ladder.csv` (колонки как у
`Run-Ladder.ps1`): `route` = `<фаза>/<маршрут>`, например `rivers/wheel/in-100`, `reopen/pan/100`; правки —
`<фаза>/edit/<команда>`, где `fps` = команд в секунду вместе с кадром после, `frameWorkP95` = p95 работы
команды в мс. Число ПК — живой замер, если в это время ПК не копирует файлы и не гоняет тесты.
