# Sol-7: проверка партии в уже открытой Map

Подготовлен сценарий; живой проход не выполнялся. Map должен быть заранее запущен владельцем или главным агентом в изолированном профиле, с открытой тестовой картой и подключённой библиотекой диска.

```powershell
Set-Location H:\MapLibrary\sol\sol7
powershell -NoProfile -ExecutionPolicy Bypass -File .\live_batch2.ps1 -SelfTest
powershell -NoProfile -ExecutionPolicy Bypass -File .\live_batch2.ps1 -ProcessId 1234 -Batch 1 -Place 10
```

Заменить `1234` на PID нужного `Map.App`. Скрипт сам Map не запускает. `-Catalog battlemaps-classic` — необязательный **точный фильтр поля `Sets[].Catalog`** в отчёте партии. Это допущение о смысле параметра `-Catalog`; путь входного отчёта фиксирован: `H:\MapLibrary\checks\batch-NNNN.json`. При фильтре проверяется только выбранная часть партии. Неизвестный каталог и пустая партия отклоняются.

`-Place 0` проверяет все выбранные карточки и снимает каталог/холст без размещения и увеличения. `-SelfTest -Batch 1 -Catalog battlemaps-classic -Place 0` ограничивает автономную проверку одним отчётом. PID для `-SelfTest` не нужен: этот режим не загружает UIA и не вызывает Win32-функции; C#-обёртка только компилируется и проверяет упаковку чисел.

Нужно держать вместе три исполняемых файла: `live_batch2.ps1`, `LiveBatchNative.cs`, `shot_target.ps1`. Входные `uia.ps1` и `click.ps1` сохранены без изменений; новый сценарий не зависит от их текстового вывода и выбора первого совпадения.

## Поведение и результаты

1. Проверяет JSON, номер партии, строки ключа/названия/каталога, отсутствие повторных ключей и ID. Считает ID по UTF-8 SHA-256 от `set-key:` + обрезанный по краям ключ, первые 32 hex.
2. Находит единственный видимый редактор внутри заданного PID. Каталог открывает только при отсутствии видимого `AssetCatalogWindow`, с ожиданием и максимум тремя попытками.
3. Сбрасывает фильтры каталога, выбирает все ассеты, группировку «Без групп», сворачивает варианты. Поиск ограничен окном каталога; выбирается видимый, доступный, непарольный элемент с записываемым `ValuePattern`. Проверяется прочитанное значение; после перестроения peers находятся заново. Диагностика кандидатов попадает в JSON.
4. Ищет каждую карточку по **точному** ID, с прокруткой виртуального `LibraryGrid` через UIA. Текущий исходник sanitizes `set-…` в `set_…`: основной ID — `GalleryCover_set_<hash>`. Дополнительно проверяется прежняя форма `GalleryCover_set-<hash>`. В событии `CoverFound` записывается фактически найденный ID. Отсутствие карточки не прерывает поиск остальных.
5. Для первых N найденных наборов выбирает карточку, закрывает каталог, при наличии нажимает `StampModeOne`, щёлкает внутри безопасной части `MapCanvas`. Координаты берутся из UIA и переводятся из физических экранных в клиентские. Каждый щелчок подтверждается ростом `MapObjectCountText` ровно на 1; другое изменение останавливает размещение и запускает уборку.
6. Снимает каталог с поиском первого набора и холст с размещёнными объектами. Затем увеличивает область вокруг первого размещения до **396–404 %**, снимает её и возвращает отправленное увеличение обратной суммой дельт. Возврат проверяется по статусу с допуском 1 процентный пункт. `Zoom400` — прочитанное значение, а не запрошенное.
7. В `finally` закрывает каталог, возвращает масштаб и выполняет по одному Undo на подтверждённый жест, сравнивая счётчик до/после каждого Undo. При расхождении автоматическая отмена прекращается. Если щелчок отправлен, но чтение счётчика оборвалось, сначала отдельно проверяет его результат; вслепую Undo не нажимается.

Каждый запуск создаёт **новую** подпапку `live\batch-NNNN-<UTC>-<suffix>` внутри Sol-7. В ней — `summary.json`, `catalog.png`, `canvas.png`, `canvas-400.png` (при успешном достижении масштаба). Отчёт пишется и при ошибке после разбора входных данных; ошибки до этого этапа выдаются в stderr. `Passed=true` требует всех карточек, запрошенного числа размещений, успешной отмены, возврата счётчика и масштаба. Код выхода: 0 при успехе, 1 при отказе. `selftest-summary.json` содержит результат последней автономной проверки.

Снимки делаются требуемым `C:\Projects\Map\tools\ai\live\mapwin.ps1 -Action shot -Title ... -Path ...`. Обёртка `shot_target.ps1` в отдельном PowerShell-процессе ограничивает внутренний `Get-Process Map.App` заданным PID, затем сверяет выбранный HWND. Другой процесс/окно и `PrintWindow=False` не принимаются. Успешный `PrintWindow` **не доказывает**, что Skia/композитор не вернул пустое или старое изображение: в отчёте стоит `VisualContentVerified=false`, PNG нужно просмотреть.

## Границы и допущения

- Только Windows PowerShell 5.1, Windows с поддержкой DPI awareness v2; права скрипта должны позволять UIA/оконные сообщения процессу Map. Минимизированное/скрытое окно и несколько редакторов внутри PID отклоняются.
- Только тестовая карта без незавершённых жестов и параллельных правок. Счётчик не позволяет отличить чужое изменение с тем же количеством объектов. Не взаимодействовать с проверяемой Map во время прохода; модификаторы Ctrl/Shift/Alt могут менять смысл колеса. Курсор скрипт не перемещает; `SendInput`, буфер обмена и явный вывод окна на передний план не используются.
- Если `StampModeOne` не доступен в дереве UIA, исходно должен быть выбран режим «Один». Иначе сценарий остановится при первом несовпадении счётчика. Undo восстанавливает объекты, но не историю Redo, выделение, инструмент, настройки каталога или возможные автосохранения. Поэтому рабочая карта владельца не подходит.
- Новый сценарий исправляет адресацию колеса: HWND редактора из UIA, координаты самого холста, физические пиксели/DPI, экранный `lParam` колеса, синхронные сообщения с тайм-аутом и подтверждение статусом. В просмотренных исходниках Map нет отдельной команды/кнопки масштаба холста. Это **не подтверждённое живое решение** старой ошибки колеса. Если новая адресация также не сработает, будет `Passed=false` с причиной, снимок «400 %» не создаётся. Для иной команды потребуется поддержка со стороны Map, править которую здесь не поручено.
- Путь события колеса подтверждён также [исходником Avalonia 12.1.1](https://github.com/AvaloniaUI/Avalonia/blob/12.1.1/src/Windows/Avalonia.Win32/WindowImpl.AppWndProc.cs): координаты колеса читаются в экранных пикселях. Там же видна причина ещё одной возможной недоставки: `IsMouseInPointerEnabled` исключает обработку `WM_MOUSEWHEEL`. Состояние запущенной сборки не проверялось.
- Проверенные исходники — текущий `C:\Projects\Map`; версия уже запущенного процесса может отличаться. Наличие нужных AutomationIds и паттернов проверяется при живом проходе. Отсутствующий ScrollPattern и слишком большой список совпадений могут помешать нахождению виртуальной карточки: предел — 100 страниц.
- Все созданные файлы, JSON, PNG и временные файлы компиляции остаются в папке Sol-7. Существующие исходники и отчёты партий читаются без изменений. Скрипты `.ps1` содержат только ASCII; русские строки приходят из JSON/UIA.
