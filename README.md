# Map — нативный офлайн-конструктор карт

`Map` — рабочее название проекта. Цель: создать самостоятельную программу для Windows (`.exe`) с функциональной глубиной современного конструктора карт, но с собственной визуальной системой и только с законно полученными или созданными нами ассетами.

Это **не сайт**, не Electron-приложение, не оболочка над браузером и не локальный веб-сервер. Предлагаемая основа — C#/.NET 10, Avalonia 12 и Skia.

## Текущий статус

- Stages 1–8, 9A, 10 input slice, 10B и production-логика 10C реализованы и имеют отдельные доказательства проверки.
- Stage 10D функционально завершён и закреплён локальным checkpoint `HEAD` branch
  `stage/10d-object-inspectors`: Release 0/0, 683/683 tests и native 13/13 прошли. До свежего
  exact-range review это `FACT` реализации / `PARTIAL` независимой приёмки, а не финально
  принятый snapshot.
- Активный coding stack: Codex `gpt-5.6-sol`, .NET SDK 10.0.400, Avalonia 12.1.1 и Skia.
- Публичное clean-room исследование и ручной walkthrough тестовой карты покрывают текущий объём; скрейпинг, декомпиляция и копирование материалов исключены.
- Точное состояние, пробелы и следующая задача ведутся в `docs/STATE_HANDOFF.md` и `docs/00_START_HERE.md`.

## Запуск production-приложения

Из корня репозитория:

```powershell
# сборка и тесты
dotnet build .\Map.slnx -c Release
dotnet test .\Map.slnx -c Release --no-build

# запуск настоящего окна (Release)
dotnet run --project .\src\Map.App -c Release
# или собранный exe:
.\src\Map.App\bin\Release\net10.0\Map.App.exe

# исторический сквозной UI smoke Stage 2B;
# не использовать как замену свежему сценарию текущего этапа
powershell -ExecutionPolicy Bypass -File .\scripts\drive-stage02.ps1
```

Локальные данные приложения: `%LOCALAPPDATA%\Map` (recent-индекс, журнал восстановления,
диагностический лог `Diagnostics\diagnostics.log`).

## Неподвижные правила

- Повторяем наблюдаемые рабочие возможности, а не код, ассеты, фирменный стиль или внутреннее устройство Inkarnate.
- Любой функционал должен работать без интернета после установки.
- Один roadmap-stage — один крупный вертикальный prompt с внутренними контрольными точками, конкретной приёмкой и проверяемым результатом.
- «Тесты зелёные» не равно «готово»: обязательны визуальные, файловые, производительные и восстановительные проверки.
- Секреты, чужие ассеты и материалы с неясной лицензией в репозиторий не попадают.

## Команда

- **Владелец проекта:** утверждает продуктовые, визуальные, архитектурные и внешние рискованные действия.
- **Codex GPT-5.6 Sol — исполнитель:** читает source of truth, реализует полный roadmap-stage внутри одного prompt, сам выбирает релевантные локальные инструменты и возвращает доказательства.
- **Свежая задача Codex — проверяющий:** независимо проверяет точный снимок, рабочее дерево, артефакты и настоящий пользовательский сценарий; не принимает самоотчёт исполнителя как факт.
