## 1. Таблица по семействам функций

### 1.1 Реки, озёра, дельты, берега, детали рек
- **Модель:** `River` (`C/Documents/River.cs:188`) состоит из `Channels`. `RiverChannel` (:54) — это узлы плюс исток и устье, а `Closed` означает озеро. В файле хранятся только узлы, контур вычисляется.
- **Правка:** `RiverCommand` (`C/Editing/RiverEditing.cs:494`) хранит снимки документов. Apply стоит O(рек в слое) и регистрирует дельту (:557-566). Черновик живёт как `RiverOverrides`, то есть только для рендера.
- **Рендер:** входит в общий «терреин» (`DrawTerrain` S:1170, `DrawTerrainPasses` S:1739). Тело реки берётся из `BodyCache` (`R/RiverRenderer.cs:22,879`): 4 записи на реку, ключ — октава ширины. Берега — LRU на 16 (`R/RiverBankRenderer.cs:60`). Готовый терреин хранится в `RenderImageCache` (6 записей, `MCC:149-150`).
- **Что делается в каждом кадре без кэша:**
  - `TerrainParts`/`Surfaces` проходят все реки и дороги всей карты (S:1198-1210);
  - `LayerSurfaces` вызывает `First` на каждую запись, это O(R²) (S:1107, 1113);
  - пересечение пути с видом `BodyTouches`;
  - `UnionOf` — N−1 операций Union над путями;
  - слой берега размером со всю реку;
  - размытия;
  - `RiverNaturalBanks` (:79-83);
  - детали реки.
- **Поток:** при отпускании правки реки или дороги `OnlyLandsDiffer` (S:1548) возвращает false, и весь видимый терреин перестраивается **синхронно в кадре** (S:1343, 1370-1388). Фоновое уточнение `TerrainRefinement` используется только для правок земли и для камеры.
- **Вырезание из земли:** `LandCuttingRivers` (S:2227) стоит «земли × реки». `CarvedLandCache` держит 3 записи. `SmoothMouths` перерисовывает все видимые плитки покрытия на каждое пересечение берега.
- **Новые ассеты:** текстура реки идёт через `MapTextureLibrary.AssetImage`. Там SHA, декодирование и уменьшение до 2048, LRU 12 (`R/MapTextureLibrary.cs:34-37,118`). Встроенные PNG декодируются под глобальной блокировкой в потоке рендера (:170-185).
- **Худший случай:** сотни рек на виде всей карты; отпускание правки даёт полную перестройку терреина в одном кадре (ASSUMPTION: сотни мс).
- **Подключение к ядру:** см. §2.

### 1.2 Дороги, перекрёстки, мосты
- **Модель:** `Road` (`C/Documents/Road.cs:211`) — общие узлы, ветки, `CrossingOverrides`.
- **Правка:** `RoadCommand` (`RoadEditing.cs:377`) хранит снимки. Перезапись SurfaceOrder стоит O(S×(R+W)) (:~425).
- **Рендер:**
  - `RoadRenderer.BodyCache` (`R/RoadRenderer.cs:949`) держит 4 записи с ключом «ширина, округлённая до 0,001» (:955), **без октав**, поэтому каждый шаг зума за полом ширины перестраивает тело.
  - В каждом кадре `Entry.Copy()` глубоко копирует пути (:66, 89), затем идут Union, обводки и `SaveLayer` по габаритам дороги.
  - **`RoadCrossings.Detect` в каждом `DrawSurfaceRun` без кэша** (S:1153): дороги × реки × ветки × каналы × сегменты (`C/Editing/RoadCrossings.cs:76-108`), не обрезано по виду.
- **Поток и худший случай:** при перетаскивании `fastTerrain` рисует простые проходы в каждом движении. При отпускании терреин перестраивается синхронно, как у рек. Худший случай — густая сеть дорог над дельтой.

### 1.3 Земля и терреин: кисти, уровни, вырезанная земля, обрывы, рельеф, море и берег
- **Модель:** `LandLayer` — плитки 256×256 (`C/Documents/TileMap.cs:31`): `GeometryTiles` (A8), `PaintTiles` (RGBA), `ReliefTiles`, `CliffWall`/`CliffBeach`, `EdgeStyle`, `Level`, `Mask`.
- **Правка:** дельты по плиткам применяются в `EndStroke` в потоке UI (`VM/EditorViewModel.Selection.cs:279-347`). Команды: `BrushStrokeCommand`, `LandPaintCommand`, `LandCliffMaskCommand`, `LandReliefCommand`. `LandRasterizer.ApplyShape` стоит O(плиток рамки × 65 536). **`ReliefEditor.Import` проходит все плитки холста**: на 131 072 px это 262 144 плитки ≈ 17 млрд пикселей (`ReliefEditing.cs:113-114`).
- **Живой мазок:** `StrokePreviewCache` + `DrawTerrainLiveOverlay` (S:1675) поверх сохранённого терреина. Для объектных слоёв `LayerImageCache` (F16, до 8192).
- **Рендер `DrawLand` (S:2276-3160) при промахе:** каждый проход заново прокручивает все видимые плитки покрытия: заливка, материал, краска, рельеф, внутренняя тень (×3), смешивания с размытием, кромка. Без поля расстояний добавляются тень и до 8 колец ряби.
- **Кэши:**
  - `TileImageCache`: 4096 записей / 256 МиБ (`MCC:149`). У поискового агента по слоям было 512 (`TileImageCache.cs:57`); это значение по умолчанию класса, а `MCC` передаёт своё.
  - `CoarseCoverage`: LRU на **256** блоков на всю программу (`R/CoarseCoverage.cs:16`), а на полной карте 131 072 px — 1024 блока на одну землю. Вид всей карты гоняет кэш по кругу и синхронно в кадре повторяет `Reduce` (:94-115).
- **Обрывы:** квадраты `LandCliffField` строятся через `Parallel.For` на половине ядер (S:2809). LRU 160 МиБ (`LandCliffField.cs:174`). При сильном приближении `SKImage.FromPixels` поля создаётся в каждом кадре для каждого квадрата (S:2836-2845). По комментарию ~15 мс на поле и 33 мс на стену.
- **Море:** `SceneRenderer.Sea.cs:24`. A8 покрытия, затем ReadPixels, EDT, массив Half[w×h×4] (~48 МБ при бюджете 6 млн) и выгрузка на GPU. Своего кэша нет, хранится только внутри готового терреина. Стиль моря входит в ключ терреина, поэтому любой ползунок моря перестраивает весь терреин.
- **Рельеф:** `SceneRenderer.Relief.cs:15-17`, бюджет 8 млн, своего кэша нет.
- **Поле берега:** `CoastDistanceField`, бюджет 24 млн, дальше плитки по 4096; до 4 раз на одну землю (S:2877-2888).
- **Холодный старт:** шейдеры SkSL (`Lazy<SKRuntimeEffect>`) компилируются при первом использовании (`LandCliffShader.cs:404`, Sea:272). Текстуры заливки (`FillTextureId`) декодируются, как в 1.1.
- **Худший случай:** вид всей карты с несколькими землями. Блоки `CoarseCoverage` гоняются по кругу, `TileImageCache` не вмещает около 5,6 тыс. плиток на виде (ASSUMPTION, расчёт). Импорт карты высот на весь холст.

### 1.4 Слои и подслои: видимость, прозрачность, маски, замки, обтравка, эффекты
- **Модель:** `MapLayer` (`C/Documents/Layers.cs:55-95`) — Visible, Locked, Opacity, Blend, Mask (A8 TileMap), `LayerEffects` (обтравка, тени, DepthSort), `ObjectSublayerState`. `StateFor` — линейный поиск.
- **Правка:** `UpdateLayerCommand` (`Commands.cs:1046`), `MaskStrokeCommand` (по плиткам), `UpdateMaskCommand`.
- **Рендер `DrawLayer` (S:1888-2007):**
  - `SaveLayer` на весь вид при маске, обтравке, прозрачности < 1 или режиме смешивания не Normal;
  - внешняя тень рисует содержимое ещё раз, внутренняя — ещё два раза, итого до ×4 за кадр;
  - `ApplyMask` рисует каждую видимую плитку маски;
  - **`FilterLayer` делает Backdrop-фильтр на весь вид в каждом кадре** (S:1927, 4441).
- **Кэш `LayerImageCache`:** ключ — сам слой плюс матрица, поэтому изменение прозрачности одного слоя перестраивает только его. Но слой подходит, только если в нём одни Normal-штампы и тексты (`Independent`, S:938-944): любая фигура, линия, украшение или композиция делает слой «некэшируемым».
- **Прочее:** `DrawCliffMaskOverlay` создаёт битмап 256 КБ на каждую плитку в каждом кадре (S:3876-3900). `CompositionFlattener` (≤ 4096) рендерит и кодирует PNG синхронно в потоке UI (`EditorViewModel.Editing.cs:1580`).
- **Худший случай:** вид всей карты с маской — до 262 тыс. плиток маски на кадр (ASSUMPTION). Слой-фильтр плюс тени.

### 1.5 Фильтры и эффекты: стили I/P/A, свет, стили моря, пресеты подписей и поверхностей, красота областей, украшения, туман, переходы
- **Стиль** (`R/Styles/StyleRenderer.cs`): пост-обработка всего кадра. Растр размером «устройство + поле + 512». Кисть — 3 F16-буфера и размытия; «Живопись» — 9 буферов (`StyleRenderer.Painter.cs:46`).
  - Ключ без самого стиля (:269), поэтому ползунок пересчитывает только `Shade`.
  - Любая правка, жест или движение камеры (кроме сдвига на целые пиксели или зума 0,5–2×) пересобирает кадр.
  - `Split` (:441-471) для каждого слоя с текстом строит новый отфильтрованный список объектов. Это O(N) и без дельты, а значит холодные индексы (ASSUMPTION о холодности).
  - Карты формы — ~4 с на один ассет горы. Строятся в фоне на половине ядер, на диске `FormMapDiskCache` до 1 ГиБ (`R/Styles/FormMapDiskCache.cs:18`).
- **Свет** (`R/Lighting/LightingRenderer.cs`): кадр сцены, затем буфер нормалей (≤ 1500 штампов выше 12 px, :21), тени на половине разрешения, затем проход SkSL на весь кадр (≤ 16 огней).
  - BuildFrame запрашивает окно в 2,5× высоты вида и сортирует **всех** кандидатов (:233-235).
  - **Ошибка:** `KeyFor` возвращает null при `options.HexAmbient` (:177), а `HexAmbient` не проверяет, есть ли на карте гекс-слой. Значит, при обычной работе освещённый кадр, видимо, не сохраняется и пересобирается при каждой перерисовке. `StyleRenderer.cs:280` проверяет HexLayer, свет — нет.
- **Мерцающие огни:** вызывают кадр каждые 41 мс.
- **Стили моря и пресеты поверхностей:** меняют ключ терреина и пересобирают весь терреин (S:1199-1203).
- **AreaBeautyRenderer:** спрайт 64×32 и DrawAtlas. Объекты с пятнами отключают быстрый путь дописывания (S:1046).
- **DecorationRenderer:** на каждый объект — SaveLayer, шум Перлина и размытие, кэша нет.
- **Туман** (`R/FogRenderer.cs`): ячейка 16 px, картинка ≤ 1024 (:17). При перестройке — 1 млн поисков в ImmutableDictionary и CPU-размытия в потоке рендера. В ключе — левая верхняя ячейка, поэтому панорама перестраивает картинку на каждом шаге ячейки.
- **Переходы:** каждый переход рисуется в каждом кадре, без отсечения по виду, с размытием на каждую метку (`TransitionRenderer.cs:17-34`).
- **Пресеты подписей:** см. 1.6.

### 1.6 Текст и подписи
- **Шрифты:** `TextFontResolver` — LRU на 64, но typeface держится через **WeakReference** (`R/TextFontResolver.cs:10-15,52`). После сборки мусора `FromFamilyName` вызывается снова в потоке рендера.
- **`DrawText` (S:4596), в каждом кадре на каждую подпись:**
  - новый `SKFont`, `Split`, `MeasureText`;
  - тень — фильтр размытия;
  - при разрядке или кривой — отдельный `DrawText` на каждый глиф;
  - текст вдоль пути (S:4671): строка, измерение и поворот на каждый глиф.
  - Кэша раскладки и атласа глифов нет.
- **`LabelPriority`** (`C/Editing/LabelPriority.cs:13-16,57`): кэш на снимок документа. Каждый новый снимок заново проходит все объекты, O(N). Разбор наложений стоит O(n²) до 4000 подписей, то есть 16 млн проверок, в первом кадре после правки.
- **Раскладка `TextOnPath`/`RegionLabels`:** делается при правке, а не в кадре. Кандидаты берутся из `BoundObjectIndex`.
- **Худший случай:** тысячи подписей с тенями при панораме.

### 1.7 Гексы
- **Модель:** `HexBoard` — куски по 16, до 2048×2048 (`C/Documents/HexBoard.cs:194-202`).
- **Правка:** `HexPaintCommand`, `UpdateHexGridCommand` (`HexEditing.cs:222,301`).
- **Кэш `HexChunkCache`:**
  - 192 МиБ картинок, 64 МиБ плоских блоков, переходы 48 МиБ, очередь 384, выгрузка ≤ 6 МиБ за кадр (`HexChunkCache.cs:17,60,231,361,417`);
  - ключ — кусок, 8 соседей и стиль;
  - строится одним фоновым рабочим;
  - **плоские дальние блоки строятся в потоке рендера** при бюджете 8 мс, причём первый строится всегда (`HexLayerRenderer.cs:107,291`);
  - импорт набора плиток очищает весь кэш (`HexChunkCache.TileSets.cs:9-15`).
- **Анимации:**
  - «Живой» мир ~24 кадра/с: **каждый такой кадр рендерит заново всю сцену, все слои**;
  - Sway — проход SkSL на кусок;
  - Ambient — до 6000 гексов за кадр (`HexLayerRenderer.Ambient.cs:14`);
  - затухания с `SaveLayer` на весь вид.
- **Холодный старт:** `HexTileArt.Warm` в фоне (`EditorView.cs:421`), а пользовательские наборы декодируются при регистрации.

### 1.8 Генерация вдоль пути (DEC-099)
- **Команда:** `PlacementPathCommand` (`C/Editing/PlacementPathEditing.cs:102-228`). Пересчитываются только изменённые сегменты, отмена проверяется каждые 512 объектов, дельты идут через быстрые пути.

### 1.13 Выделение, перемещение, трансформация, удаление, порядок
- **Клик:** `HitTest` (`C/Documents/SceneGeometry.cs:140-189`) делает `QueryPoint` на каждый слой, с копией `_oversized` в HashSet и сортировкой. Рамка выделения — через пространственный запрос.

  - `SelectHit`/`SetSelection` — `Contains` по `List`;
  - `ToggleSelection` — `List.Contains` (`EditingSession.cs:79`);
  - `SelectedObjects` создаёт новый список на каждый вызов, а вызывают его и в каждом кадре (`SelectionFrame`).
  - `SelectionRefreshDelta.Capture` строит ImmutableHashSet всего выделения на каждое изменение.
- **Перетаскивание:**
  - `UpdateDragTo` создаёт S новых объектов на каждое движение;
  - переопределения отключают плотные плитки (S:3224);
  - словарь переопределений строится на каждый слой в каждом кадре (S:3265);
  - **`FindRenderObject` вызывает `FirstOrDefault` по переопределениям на каждый выделенный id — O(S²) на кадр** (S:6499-6502, вызывается из 5634-5644).
- **Конец перетаскивания:** `ReplaceObjectsCommand` через `ReplaceObjects`. При S > 1024 индекс ревизий сбрасывается и строится заново в потоке UI (~1,3 с на 1 млн по цифрам 9c83d85, ASSUMPTION для этого случая).
- **Удаление** (`Commands.cs:828-916`):
  - три полных прохода всех объектов, ещё один в `RemoveObjectsCommand` (631);
  - Apply строит список через `[.. Where]` (651), отсюда `WithLayers` → полная проверка и все индексы холодные;
  - Revert — `ToList` плюс `Insert`, O(N·k).
- **Те же медленные пути:** `PasteObjectsCommand.Revert` (333), `ReorderObjectsCommand` (577-588), `MoveObjectsToLayerCommand` (через Remove).
- **Панель объектов:** `ObjectTree` пересобирается при каждом обращении (`Selection.cs:677-680`). `InDrawOrder` — O(N) на новый список. `UiWorkQueue` — 16 строк и 4 мс на порцию.

### 1.14 Undo/Redo
- **Дельтовые команды:** замена (2S объектов), добавление, удаление (индекс и объект).
- **Команды-снимки (целые документы):** путь, область, генерация, материк, гексы, `UpdateLayerCommand.Replace`.
- Undo снимка стоит O(1). Undo добавления — быстрый splice. **Undo удаления — O(N·k) плюс полная проверка.**
- Предела истории нет. `EditCost` (128 КиБ + 4 КиБ на объект) используется только для допуска.

### 1.15 Сохранение, открытие, автосохранение, восстановление
- **Автосохранение:** таймер в потоке UI, 60 с (10–3600) (`Map.App/MainWindow.cs:171-177`; `AppSettingsStore.cs:13-21`), откладывание на 4 с после правки (`VM/EditorViewModel.cs:1091`).
- **В потоке UI:**
  - снимок O(1);
  - **но `new ExportStampImageSource` = O(записей каталога) на каждое сохранение** (`EditorViewModel.cs:1146,1196,1346`; `S/ExportStampImageSource.cs:34-48`).
- **В фоне:**
  - миниатюра 320×180 по **всем** N объектам;
  - `WriteObjectChunks` — JSON на каждый объект, куски 8192 объекта / 8 МиБ, SHA, Deflate Optimal;
  - **`ValidateReadBack` перечитывает весь файл и сериализует каждый объект ещё дважды** (`MapProjectStore.cs:733,1699-1723`).

- **Открытие:** чтение кусков последовательное, без параллельности. Построение `EditorViewModel` в потоке UI.
- **После сбоя:** `FindRecoveryCandidates` полностью открывает каждый снимок **в потоке UI** при показе стартовой страницы (`DashboardViewModel.cs:319`; `AutosaveSnapshots.cs:181`).
- **Встроенные текстуры (v55):** обычные встроенные ассеты, переписываются целиком при каждом сохранении.

## 2. Как подключить каждое семейство к общему ядру

Принципы ядра:
- **(а)** Кадр не ждёт: используется лучшая готовая замена, а точный вид готовится в фоне, как `TerrainRefinement` и `HexChunkCache`.
- **(б)** Правка в потоке UI — только O(изменённое). Всё O(N) уходит в фон по снимку и применяется, если ревизия не сменилась (образец — `BackgroundGeneration`).
- **(в)** Каждый дорогой результат — чистая функция (снимок, вид, опции). Его можно кэшировать по ссылкам на неизменяемые части и нарезать порциями.
- **(г)** Регулятор качества меняет только промежуточные кадры, итоговый кадр после остановки всегда точный.

| Семейство | Как подключить |
|---|---|
| Реки | Отпускание правки — через `TerrainRefinement` с участком «старые ∪ новые габариты + `TerrainEffectReach`» вместо синхронной перестройки (обобщить `OnlyLandsDiffer`). Кэшировать `Surfaces`/`TerrainParts` по ревизии. Словари вместо `First`. Union и `BodyTouches` кэшировать по группе. |
| Дороги | То же для отпускания. Кэшировать `RoadCrossings.Detect` по паре (дорога, река). Ширину квантовать по октаве. Убрать `Copy()` в кадре. |
| Земля и терреин | Поля моря, рельефа и берега кэшировать по (ссылки плиток, вид, тексель) и строить плитками в фоне. Размер `CoarseCoverage` и `TileImageCache` считать от холста и вида. Шейдеры обрывов хранить, а не создавать в кадре. Импорт рельефа и большие `ApplyShape` — фоновая работа с превью. Заранее прогревать SkSL и текстуры при открытии. |
| Слои | Хранить результат слоя с фильтром и тенями в `LayerImageCache` для неподвижного вида. Расширить `Independent` на фигуры с Normal. Битмапы маски обрывов — в кэш плиток. |
| Стили и свет | Исправить ключ света (`HexAmbient` только при наличии гекс-слоя). `Split` — по дельтам, без новых списков. Кадр стиля и света — фоновое уточнение после жеста, во время жеста — готовый кадр. Туман — по ячейкам с запасом вокруг вида, вне потока рендера. Переходы отсекать по виду. |
| Текст | Кэш раскладки глифов и пути по (текст, стиль, шрифт), сильные ссылки на шрифты. `LabelPriority` пересчитывать по дельтам, наложения — сеткой вместо n². Тени — растром в кэш. |
| Гексы | Анимацию рисовать поверх готового кадра без гексов, а не перерисовывать все слои. Частота анимации — по бюджету регулятора. Плоские блоки строить в рабочем потоке. Импорт набора инвалидирует только затронутые плитки. |
| Генерация вдоль пути | Уже фоновая. Проверки владения (`Allows`) — по дельте изменённых id, а не по всем членам. |
| Области | Применение и перегенерация — через фон и быстрые дельты без `ToImmutableArray`. `LabelBounds` и `SelectionArea` — индексы по ревизии. Сжимать `_structuralOverrides` в фоне. |
| Мир и материк | Уже фоновые. Применение — `WithRevisedLayers` с дельтой, когда состав слоёв не меняется. |
| Город | `CityBuilder.Generate` — через `BackgroundGeneration`, слой — через быстрые дельты. |
| Штампы | Россыпь: план в фоне (детерминирована по зерну), предел на один клик, превью AvoidOverlap ограничить. Стирание — пространственным запросом и `RemoveIds`. Плотные плитки не отключать для всего слоя из-за одного холодного ассета. Только эту картинку рисовать временной заменой. Синхронное декодирование в рендере убрать. |
| Выделение и перемещение | Только HashSet; словарь переопределений строить раз за кадр. Предел наложения 1024 убрать или сжимать в фоне. Удаление, порядок и перенос — через `RemoveIds`/`InsertMany` с дельтой. Кадры камеры разрешить при выделении: рисовать обводку поверх готового кадра. |
| Undo | Предел истории по байтам (`MeasuredWorkingBytes`). Undo удаления — через `InsertMany`. |
| Сохранение | `ExportStampImageSource` строить один раз на ревизию каталога и не в UI. Проверку записи вести по SHA кусков вместо двойной сериализации. Кэшировать байты неизменённых кусков. Миниатюру брать из готового обзора. Поиск восстановления — в фоне. Автосохранение — низкий приоритет при перегрузке кадра. |
| Экспорт | План в фоне или по ревизии. Общий с холстом кэш картинок через неизменяемые «аренды». Все экспорты — под одни ворота и бюджет. Во время интерактива регулятор уменьшает число рабочих. |
| Каталог | `RefreshLibrary` — через `QueryAsync`. Фильтры кэшировать по ревизии. Импорт (SHA, миниатюра, лестница) — фоновая очередь DEC-107. Сохранение каталога без ожидания. Подключить `DerivedCacheJanitor` как простой фоновый процесс. Переработка строк галереи. |
| Изменение холста, таймлайн, окно игрока | Превью — в фоне с отложенной отменой. Вид таймлайна — замены рендера (overrides) поверх исходного слоя, а не новый документ. Или строить его в фоне и рисовать старый, пока новый не готов. |
