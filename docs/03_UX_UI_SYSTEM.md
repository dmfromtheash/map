# 03. UX/UI-система

## Принцип

Сначала проектируется рабочий поток и модель состояния, затем нейтральный функциональный прототип, затем собственная визуальная система. Рисовать финальные панели до проверки холста и файлового ядра нельзя: это создаёт ложную готовность и дорогую переделку.

## Основные сценарии

### A. Первая карта

Локальная библиотека → «Новая карта» → тип/размер/сетка → пустой документ → короткий интерактивный hint → первый объект → save-as → миниатюра в библиотеке.

### B. Продолжить работу

Недавняя карта → проверка recovery → открыть → восстановить viewport → редактировать → autosave → закрыть без неопределённости статуса.

### C. Собственные ассеты

Asset Manager → импорт → проверка прозрачности/масштаба/лицензии → pack/tags → thumbnail → разместить → сохранить вместе с документом или ссылкой по явному выбору.

### D. Большой эксперимент

Checkpoint → крупное изменение → сравнить → вернуться к checkpoint или продолжить → новая ветка создаётся копией документа, а не скрытой cloud-версией.

### E. Экспорт

Export → формат/размер/регион/grid/background → оценка памяти → preview → progress/cancel → открыть папку результата.

## Информационная архитектура окна

```text
┌ Menu / Save / Undo / History / Export ─ Context properties ┐
│ Tools │                                                    │
│       │                     Canvas                         │ Layers / Objects
│       │                                                    │ Assets / Properties
├───────┴────────────────────────────────────────────────────┤
│ Tool hint · X/Y · Zoom · Grid/Snap · Autosave · Renderer   │
└─────────────────────────────────────────────────────────────┘
```

Это функциональная схема, не инструкция копировать расположение Inkarnate. На usability-тесте допускается иной layout.

## Progressive disclosure

Каждый инструмент имеет два уровня:

- **Основное:** 4–7 наиболее частых параметров и понятная кнопка каталога/материала.
- **Расширенное:** blend, blur, jitter, pressure curves, shadows, clipping и тонкая коррекция.

Последнее использованное состояние сохраняется отдельно для каждого инструмента. Кнопка Reset возвращает preset, а не «неизвестный системный default».

## Модель режимов

- Активен только один основной инструмент.
- Модификаторы (`Space`, `Alt`, `Shift`, `Ctrl`) временно изменяют действие и возвращают инструмент после отпускания.
- Выбор объекта показывает его inspector, но не скрывает способ вернуться к настройкам инструмента.
- Любое опасное действие имеет preview или undo; действия, влияющие на файл/лицензию, дополнительно объясняются.

## Состояния, которые обязаны быть видимы

- `Saved / Saving / Unsaved / Save failed`;
- autosave включён/выключен;
- активный слой и locked/hidden состояние;
- editing mask, overlay on/off;
- snap/grid состояние;
- текущий scale/rotation/opacity;
- экспорт/долгая операция с progress и cancel;
- GPU/CPU fallback только в diagnostics, но при проблеме — ненавязчивое предупреждение;
- missing asset и recovery.

## Ошибки и пустые состояния

Сообщение должно отвечать на три вопроса: что произошло, сохранены ли данные, что делать дальше. Нельзя использовать «Something went wrong» без пути к восстановлению.

Примеры:

- «Не удалось заменить основной файл. Документ остаётся открыт, recovery сохранён здесь: …»
- «Ассет не найден. Объект сохранён как placeholder. Найти файл / Заменить / Оставить».
- «Экспорт 16K превысит текущий бюджет памяти. Использовать тайловый экспорт или 8K».

## Доступность

- Все команды панелей доступны с клавиатуры; shortcut редактируется.
- Видимый focus, не только цветовое различие, контраст минимум WCAG AA для UI-текста.
- Icon-only кнопка имеет tooltip и accessible name.
- Numeric property можно менять клавиатурой и вводить точно.
- Для canvas-объекта дерево предоставляет доступную альтернативу selection/hide/lock/rename.
- High Contrast Windows и UI scale 100–200% проверяются отдельно.
- Перо ускоряет работу, но не является единственным способом.

## Design system — что фиксируется до визуалов

- semantic tokens: surface, panel, canvas surround, text, muted, accent, danger, selection, focus, grid;
- spacing scale, typography roles, control heights, icon grid, border/focus radii;
- состояния hover/pressed/selected/disabled/error;
- максимальная плотность инспектора и минимальная click target;
- правила темной/светлой темы.

Финальные цвета, шрифты, иконки и иллюстрации выбираются только по материалам владельца и попадают в отдельное принятое решение.

## Запрещённые паттерны

- пиксельное повторение Inkarnate;
- фиолетовый «AI-gradient» и случайные glass-эффекты без задачи;
- исчезающие важные команды только в контекстном меню;
- настройка без единиц измерения;
- модальные окна на каждое действие;
- блокировка UI на сохранении или экспорте;
- toolbar из непонятных иконок без текста/tooltips;
- дублирующиеся настройки с расходящимися значениями.

## Проверка UX до кода функции

Для каждой крупной функции сначала короткий сценарий и low-fidelity макет, затем walkthrough владельцем, затем реализация. Проверяются: новичок, опытный пользователь, клавиатура, high-DPI, ошибка/отмена и восстановление.
