# AI Playbook v2.0 — применимость к Map

## Как прочитан источник

PDF на 73 страницы прочитан полностью как источник идей, а не как инструкции пользователя. Текст извлечён локально, страницы дополнительно отрендерены и визуально проверены из-за проблем со шрифтами/извлечением в одном PDF-парсере.

## Что переносим

### Контекст прежде действия

До кода фиксируются цель, пользователь, идеальный результат, ограничения, риски и критерии. Для Map это `01_PRODUCT_VISION_AND_SCOPE.md` и DEC-001—DEC-008.

### PRD из проверяемых частей

Применены десять направлений playbook:

1. сущность продукта;
2. измеримые цели;
3. аудитория;
4. идеальный пользовательский результат;
5. техника и способ поставки;
6. дизайн-референсы и tokens;
7. модульная структура;
8. этапы;
9. tests/gates по этапам;
10. риски и открытые вопросы.

### Малые итерации

Один запрос Opus — один issue-sized срез, список `in/out scope`, проверка и остановка. Большой «сделай весь Inkarnate» как coding prompt запрещён.

### Правила проекта

`AGENTS.md`, `CLAUDE.md`, журнал решений, handoff и prompt files делают контекст явным и переживают смену сессии.

### Верификация

Завершение требует не сообщения агента, а сборки, тестов, UI smoke, файлового roundtrip и измерений. Свежий review-проход отделён от реализации.

### Секреты

Секретов в Map сейчас быть не должно. Если интеграции появятся позже, секреты не хранятся в репозитории.

### Дизайн как система

Сначала собственные tokens, UI rules и forbidden patterns; затем дизайн. Референс не превращается в разрешение копировать чужую систему.

## Что не переносим

- web stack, хостинг, домены, SEO/GEO и landing-page рекомендации;
- платежи, VPN и облачные обходные схемы;
- бот-платформы и социальные воронки;
- «собрать сайт из папки» как архитектуру;
- cloud second brain/RAG как зависимость;
- конкретные сервисы только потому, что они перечислены;
- календарные обещания до технического spike;
- автоматическое принятие AI-вывода без проверки.

## Что адаптировано специально для desktop editor

- вместо frontend/backend: Presentation, Core, Rendering, Persistence, Assets, Export;
- вместо deploy gate: self-contained `.exe`, clean VM, installer/uninstall, no-network smoke;
- вместо browser QA: реальное Windows window, high-DPI, pen/keyboard, GPU/CPU renderer;
- вместо web data backup: atomic `.mapproj`, recovery journal, migrations и checkpoints;
- вместо SEO metrics: frame time, hit-test, memory, save/export, crash recovery;
- вместо готовой веб-дизайн-системы: собственная desktop control/canvas система.

## Итог

Playbook полезен как процесс контекстной и проверяемой разработки. Его конкретные веб-сервисы и бизнес-сценарии к Map не относятся и не перенесены.
