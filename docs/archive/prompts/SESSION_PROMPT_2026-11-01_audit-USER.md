## Цель
Детальный аудит Map по уровням **бэкенд → фронт → UI → UX** (плюс оптимизация), выполненный **на втором ноутбуке
владельца USER**, с Астрой (ChatGPT, `gpt-6-astra`) как вторым исполнителем, «используй его полностью для всего насколько
возможно». Слова владельца: «прогнать проект максимально по разным уровням… Все тесты, от оптимизации до удобства и
визуала. Снимайте скрины и изучайте всё, как что нажимается и открывается, что налазит и вылазит, что работает а что
нет. Не делайте всё параллельно. Делайте по кускам». Решение — DEC-083.

**Входит:** проверки, снимки, замеры, отчёты, список проблем с приоритетами. **Не входит:** исправления кода, новый арт,
коммиты кода — только по отдельному слову владельца после отчёта куска. Аудит выдаёт выводы.

## Астра на USER (DEC-081 + DEC-083)
Запуск только так (из сеанса SSH; stdin закрыть, иначе висит; песочница `elevated` из сеанса 0 не стартует):
```
cmd /c "\"%APPDATA%\npm\codex.cmd\" exec --skip-git-repo-check -m gpt-6-astra -c model_reasoning_effort=\"xhigh\" -s read-only -c default_permissions=\":read-only\" -c windows.sandbox=\"unelevated\" \"<задание>\" < NUL"
```
Рабочая папка `C:\Projects\Map` на USER. По умолчанию в её config — Sol, поэтому `-m gpt-6-astra` обязателен. После
каждого запуска — сверить `"sandbox_policy":{"type":"read-only"}` и `"model":"gpt-6-astra"` в последнем
`C:\Users\user1\.codex\sessions\**\*.jsonl`. Длинные задания — в фоне с записью в файл. Астра код не меняет; каждый её
вывод Claude перепроверяет по коду или прогоном (FACT/PARTIAL/NOT CHECKED). Визуал оценивает только Claude. Перед
первым запуском подтвердить у владельца уровень (план — xhigh), если он не сказал иначе в начале сессии.

## Куски (строго по очереди; после каждого — отчёт владельцу и его «дальше»)
0. **Сеть (коротко, до аудита).** Владелец: «всё ещё какая-то фигня с сетевыми учётными данными». На USER диск
   `Z: \\DM\HomeShare` — «Unavailable» (папка `C:\HomeShare` на DM, локальная учётка `homeshare`). Спросить, где
   и какой текст ошибки; чинить по ответу (обычно `net use Z: /delete` + новое подключение с `DM\homeshare`).
   Пароли — вводит владелец, в чат и файлы не писать. Учётные хранилища не читать.
1. **projmap — карта кода.** `projmap-cli scan C:\Projects\Map` и `report` на USER → graph/отчёт; горячие места:
   крупные файлы и классы, циклы, связность UI↔Core, частые совместные изменения в git, мёртвый код
   (`AvailableObjectLayerTargets` уже известен). Астра параллельно не работает — отдельным шагом читает отчёт и
   предлагает гипотезы; Claude сверяет.
2. **Бэкенд** (`Map.Core`, документ, Undo, атомарное сохранение, схема v47, рендер/`SceneRenderer`/`StyleRenderer`,
   экспорт). Тесты затронутых проектов (собрать тестовый проект перед `--no-build`, STATE), анализаторы (IDISP 217,
   VSTHRD 37 — разобрать, что из них реальные утечки/блокировки). Астра — ревью инвариантов «Core не зависит от UI»,
   «рендер не меняет документ», гонки фоновой подготовки стилей.
3. **Фронт** (`Map.Presentation` ViewModel, `Map.App` Views). Нагрузка и отклик: смоуки `tools/Map.Performance`
   по одному профилю за раз (`native-paint-perf`, `editor-integrity`, `placement-workflow` — предел 2 560 МиБ, пакет
   В7: щелчок по тяжёлому стилю 13–25 с). Сравнить числа USER (GTX 1070, 7700HQ) с DM — это и есть ценность второй машины.
   `dotnet build-server shutdown` перед смоуками.
4. **UI.** Живой проход по разделам программы на экране USER со снимками: что налазит, обрезается, вылазит за окно,
   не нажимается, мигает; DPI 100 % на USER против 125 % на DM. Не `--ui-tour` целиком — по разделам, кусками.
   Правило DEC-082 (одна функция — одно место) проверить на каждом экране.
5. **UX.** Сценарии владельца целиком: создать карту → суша/горы его ассетами → реки/дороги → области → «Вид»
   (свет/стиль/море) → сохранить → открыть → экспорт PNG. Где непонятно, где лишний шаг, где не найти функцию
   (память `feedback-ui-overloaded`). Каждая находка — путь в программе, снимок, что ожидалось.

## Отчёт каждого куска

налезает (проверить снимком страницы headless Chrome). Для каждой проблемы: где (путь в программе или файл:строка), что
видно, почему плохо, насколько важно (сломано / мешает / косметика), FACT/PARTIAL, кто нашёл (Claude/Астра/projmap).
В чат — коротко по-русски и ссылка. В конце сессии — сводный список всех кусков с приоритетами и предложенный порядок
исправлений (PROPOSED).
