# 00. Чек-лист этапа Map

Короткий обязательный чек-лист для любого исполнителя (DEC-054 заменяет длинную форму DEC-051).
Правила — в `AGENTS.md`; подробности, команды и списки — в `docs/00_STAGE_REFERENCE.md` (§C–§M).
Этап — любое поручение, после которого меняются код, документы или инструменты.

## Чек-лист

| № | Шаг | Как |
|---|---|---|
| 1 | Поручение понято; этап не отложенный (R36/R37 — только после «да» владельца) | процитировать поручение одной строкой |
| 2 | Правильная папка и чистый старт | `Get-MapContext.ps1 -AsJson`: продуктовая папка, ветка, HEAD, чужие изменения не трогать |
| 3 | Прочитан `docs/STATE.md` и только относящееся к задаче | раздел спецификации, DEC, запись журнала по теме |
| 4 | Карточка этапа: результат, входит / не входит, **список файлов**, как проверить | 4–8 строк в начале работы (шаблон ниже) |
| 5 | Стоп-условия проверены | §H справочника; при совпадении — спросить владельца до работы |
| 6 | Отвергнутые подходы не повторяются | §I справочника |
| 7 | Работа шагами по списку (TodoWrite / update_plan), правки инструментом редактирования | BOM/CRLF как в HEAD |
| 8 | Проверка по типу изменения, один раз | `AGENTS.md §Проверка`, таблица §D справочника |
| 9 | Diff просмотрен: только файлы из карточки этапа | `git diff --stat`; `tools/ai/Check-Scope.ps1` |
| 10 | Документы: запись в журнал, `STATE.md` переписан, DEC/CHANGELOG при необходимости | `AGENTS.md §Документы после этапа` |
| 11 | Commit → push ветки → push `main` → CI зелёный | §F справочника |
| 12 | Мусор убран: тестовые карты, профили, снимки, выгрузки вне `artifacts/<тема>` | `git status` чистый |

## Карточка этапа (пишется в начале работы, повторяется в отчёте)

```
Этап: <название / номер дорожной карты>
Результат: <что получит владелец>
Входит: …            Не входит: …
Файлы: <пути или папки, которые разрешено менять>
Готово, когда: <проверяемое условие и какие проверки>
```

Файлы вне списка можно менять, только объяснив в отчёте почему.

## Отчёт

1. Карточка этапа.
2. Что сделано (файлы, классы, имена контролов) и коммиты.
3. Проверено: команды и числа (`N/N`, CI-run). Не проверено: что и почему.
4. Пункты чек-листа, которые **не** выполнены или не нужны, — с причиной. Выполненные не
   перечислять построчно.
5. `## ИТОГИ` по `AGENTS.md`.
