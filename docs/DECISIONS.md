# Журнал решений

Записи не редактируются задним числом. Новое решение либо принимает предложенное, либо помечает старое как `superseded` ссылкой на новый ID.

## DEC-001 — Нативная офлайн-программа

- **Статус:** `accepted`
- **Принято владельцем:** 2026-08-25
- **Дата:** 2026-08-25
- **Решение:** основной продукт — нативное Windows-приложение. Запуск, редактирование, сохранение и экспорт не требуют браузера, локального веб-сервера или интернета.
- **Причина:** прямое требование владельца.
- **Следствия:** Electron, Tauri, WebView, PWA и обязательный cloud backend не используются.

## DEC-002 — Технологический стек

- **Статус:** `accepted`
- **Принято владельцем:** 2026-08-25
- **Дата:** 2026-08-25
- **Решение:** C# 14 / .NET 10 LTS, Avalonia 12.1, прямой Skia-рендеринг сложного холста, CommunityToolkit.Mvvm для UI-состояния.
- **Причина:** нативное окно Windows без Chromium, MIT-лицензии, быстрый цикл для Opus, доступ к аппаратному и программному рендерингу, нормальная упаковка `.exe`.
- **Альтернативы:** Qt 6/C++ сильнее как зрелый scene framework, но повышает сложность и лицензионную нагрузку; Godot удобен для 2D, но хуже подходит к доступному document-centric desktop UI.
- **Ворота:** подтвердить spike с 10 000 объектов, пером, маской и offscreen export до принятия.

## DEC-003 — Чистая функциональная реализация

- **Статус:** `accepted`
- **Принято владельцем:** 2026-08-25
- **Дата:** 2026-08-25
- **Решение:** повторять только наблюдаемую функциональную семантику; использовать собственную информационную архитектуру, код, терминологию, визуальный язык и ассеты.
- **Причина:** защита проекта от лицензионных, договорных и репутационных рисков.

## DEC-004 — Граница офлайн-паритета

- **Статус:** `accepted`
- **Принято владельцем:** 2026-08-25
- **Дата:** 2026-08-25
- **Решение:** функциональный паритет относится к локальной библиотеке карт, редактору, каталогу ассетов и экспорту. Аккаунты, тарифы, Community Explore, Marketplace, публикация, социальные функции и cloud sync не входят.
- **Локальные эквиваленты:** Marketplace → локальные пакеты ассетов; My Maps → локальная библиотека проектов; cloud history → локальные checkpoints и recovery.

## DEC-005 — Формат проекта

- **Статус:** `accepted`
- **Принято владельцем:** 2026-08-25
- **Дата:** 2026-08-25
- **Решение:** версионированный ZIP-контейнер `.mapproj` с JSON-манифестом/сценой, встроенными собственными ассетами, миниатюрой и контрольными суммами.
- **Причина:** переносимость, возможность инспекции/восстановления и миграций без скрытой базы данных.

## DEC-006 — Сначала риск-спайк, затем полный UI

- **Статус:** `accepted`
- **Принято владельцем:** 2026-08-25
- **Дата:** 2026-08-25
- **Решение:** после UX-каркаса проверить рендеринг, ввод, undo и файловое сохранение на техническом spike. Полный визуальный дизайн и ассеты развивать после доказательства основы.
- **Причина:** главные риски — холст, память, история и надёжность файлов, а не оформление панели.

## DEC-007 — Windows x64 как первая поставка

- **Статус:** `accepted`
- **Принято владельцем:** 2026-08-25
- **Дата:** 2026-08-25
- **Решение:** первая версия поддерживает Windows 10/11 x64. arm64 и другие ОС рассматриваются после стабильного MVP.
- **Причина:** узкая проверяемая матрица первой поставки.

## DEC-008 — Автосохранение и восстановление обязательны до расширенных инструментов

- **Статус:** `accepted`
- **Принято владельцем:** 2026-08-25
- **Дата:** 2026-08-25
- **Решение:** атомарное сохранение, backup, recovery и именованные checkpoints входят в основу до дорогих фильтров и расширенного scatter.
- **Причина:** потеря пользовательской работы — критический дефект редактора.

## DEC-009 — Очень большие карты, deep zoom и 16K+ являются архитектурным требованием

- **Статус:** `accepted`
- **Принято владельцем:** 2026-08-25
- **Дата:** 2026-08-25
- **Решение:** продукт не ограничивается типовой 4K/8K картой. Движок обязан поддерживать очень
  большой логический canvas, сильное приближение с сохранением доступной исходной детализации,
  16K export и export больше 16K тайлами/регионами без создания единого full-canvas bitmap.
- **Архитектурные следствия:** spatial culling, tiled raster storage, mip/LOD, bounded RAM/VRAM
  caches, фоновая подгрузка видимых данных, один scene evaluator для viewport/preview/export и
  отсутствие операций, стоимость которых скрытно пропорциональна площади всей карты.
- **Честная граница:** zoom не создаёт деталей сверх векторной геометрии или исходного разрешения
  ассета; UI должен показывать качество/LOD, а не обещать несуществующую детализацию.
- **Ворота:** минимальные измеримые профили фиксируются в roadmap и могут быть повышены только по
  фактическим benchmark; снижать их скрытно нельзя.

## DEC-010 — Функциональный паритет панели объекта и сеток

- **Статус:** `accepted`
- **Принято владельцем:** 2026-08-26
- **Дата:** 2026-08-26
- **Решение:** Map должен покрывать наблюдаемые инструменты выделенного stamp: replace asset,
  scale/rotation/sublayer, оба flip, opacity, shadow, blend, blur и Hue/Saturation/Brightness/
  Contrast; Shape получает прямое редактирование fill/stroke и общих эффектов. Grid panel должен
  открыть square, diagonal diamond, hex-flat и hex-pointy presets и все уже существующие точные
  параметры сетки.
- **Граница:** паритет относится к функции и результату. Названия, компоновка, tokens, icons,
  assets и visual language остаются собственными согласно DEC-003.
- **Gate:** поле в модели или renderer не считается готовой функцией без доступного control,
  фактического значения, одной undoable-команды, save/reopen и preview/export проверки.
- **Доказательная матрица:** `docs/research/OBJECT_AND_GRID_PARITY.md`.
