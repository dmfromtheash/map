# 07. Короткий рабочий цикл Codex

## Цель

Быстро улучшать личное приложение владельца без процессной бюрократии и без потери его данных.

## Цикл

1. Проверить текущую ветку, `HEAD` и незакоммиченные файлы.
2. Проверить `git log --all` и последний product HEAD в `STATE_HANDOFF`; не начинать новый stage
   от старого checkout.
3. Прочитать только относящуюся к задаче спецификацию и активный stage-контракт.
4. Внести минимальное изменение production-кода.
5. Выполнить одну соразмерную проверку.
6. Кратко сообщить результат, непроверенное и закончить разделом `ИТОГИ` по обязательному формату
   из `AGENTS.md`.

Если уборка находится на старой ветке, её intent переносится поверх latest product HEAD. Нельзя
«упростить» работу откатом уже выполненных Stage 10/11 функций.

## Какая проверка соразмерна

| Изменение | Проверка по умолчанию |
|---|---|
| Документация | перечитать diff |
| Локальная чистка/настройка сборки | Release build production solution |
| Узкая доменная логика | Release build + один test filter/project |
| UI | Release build + один сценарий в текущем окне |
| Сохранение/открытие | адресный roundtrip/failure test, без полного suite |

Не используются без прямого запроса: чистая VM, отдельный review-agent, full-suite, mutation,
coverage, benchmark, SBOM, installer, signing, pre-commit и большие evidence-папки.

## GitHub

Перед любым GitHub-действием прочитать `docs/GITHUB_PROJECTS.md`. Read-only проверка remote/auth
разрешена; создание repository/Project/issue, изменение token scope и push требуют прямого
разрешения. Недоступный GitHub Project не блокирует локальную функцию Map.

## Когда остановиться и спросить

Только если требуется новое продуктовое решение, платная/внешняя операция, публикация, секрет,
необратимое удаление данных владельца или существенное расширение задачи.
