## 3. Как определить, что делать

- Текущий этап = первая строка таблицы в PROGRESS со статусом `🔄` или, если такой нет, первая `⬜`, у которой все этапы из «Зависит» имеют статус `✅`.
- Если у первой `⬜` не закрыта зависимость, а та зависимость `⏳` ждёт владельца, бери следующий выполнимый этап. Причину запиши в журнал.
- Никогда не начинай два этапа одновременно.

## 4. Цикл одного этапа (повторять до конца дорожной карты)

1. **Объяви старт** одной строкой: `▶ Этап N/44 — R## <название> (пункты: …). Завершено: K из 44.`
2. **Чек-лист этапа в PROGRESS:**
   - перенеси в блок «Чек-лист текущего этапа» все условия «Готово, когда» из дорожной карты и обязательные строки (A1–A8, проверки D, handoff, commit/push, обновление таблицы);
   - поставь этапу статус `🔄`;
   - сразу сохрани файл.
3. **Протокол A и B:**
   - пройди A1–A8 и B1–B8;
   - сформулируй результат, границы «входит / не входит», условие «готово» и список проверок (3–6 строк);
   - проследи одну операцию пользователя: ввод → ViewModel → команда → документ → рендер → save/reopen/export.
4. **Стоп-условия (§H протокола, пометки ⛳ и 🎨 в дорожной карте):**
   - если этап требует решения владельца, задай **все** вопросы этапа одним сообщением (с вариантами и рекомендацией) и запиши их в «Вопросы владельцу»;
   - 🎨: сначала макет. Artifact с 2–3 вариантами (§B8). Внедрять только выбранный;
   - **Не простаивай.** Пока ждёшь ответа, делай части этапа, которые от ответа не зависят. Если таких нет — ставь `⏳ ждёт владельца (что)` и бери следующий выполнимый этап.
   - Не задавай вопросов, на которые отвечают дорожная карта, протокол или код. Владелец не любит лишних вопросов.
5. **Реализация (C1–C7):**
   - небольшими вертикальными срезами: UI-кнопка, Undo, save/reopen, экспорт, если этап его касается;
   - новое пиши в предметных контроллерах и partial-файлах, не раздувай `EditorViewModel.cs` / `EditorView.cs` / `SceneRenderer.cs` (D12);
   - кодировку и CRLF сохраняй как в HEAD;
   - новая версия схемы `.mapproj` — только если этап её предусматривает: следующий свободный номер, миграция, старые v4…vN открываются, обновить `docs/05`;
   - имена контролов для смоуков: `…Button`, `…Slider`, `Tag="Reveal:…"`;
   - новый или расширенный смоук-профиль в `tools/Map.Performance`.
6. **Проверка (раздел D протокола) — по типу изменения, каждая один раз:**
   - Release-сборка;
   - адресные тесты;
   - для широких правок — тестовый проект целиком со сверкой с §J;
   - смоук и живой проход в изолированном профиле;
   - A/B медианами для производительности;
   - save → reopen;
   - экспорт;
   - визуальное сравнение.

   Снимки — только окна Map через PrintWindow. Окно и данные владельца не трогать. Если проверка падает — чини в этом же этапе. Давние падения из §J — не регрессия, но новое падение — регрессия.
7. **Документы (E1–E6):**
   - верхняя секция `docs/STATE_HANDOFF.md`: FACT, «Проверено» с числами, NOT CHECKED (всегда «живой просмотр владельцем», если его не было), «Следующий шаг», хеши;
   - DEC, если было решение владельца;
   - `CHANGELOG.md`, затронутые `docs/0x`.
8. **PROGRESS:**
   - отметь все `- [x]` в чек-листе этапа (с доказательством в скобках: число тестов, путь отчёта, хеш);
   - в таблице поставь статус `✅`, коммит(ы), дату;
   - обнови сводку: «Завершено: K+1 из 44», «Текущий этап: следующий», «Последний коммит»;
   - перенеси чек-лист в «Журнал» записью `### <дата> · R## <название> · ✅ · этап N/44` (3–8 строк);
   - в блок «Чек-лист текущего этапа» положи чек-лист **следующего** этапа.
9. **Git (F1–F6), по одной команде на действие:**
   - `git status --short` (только свои файлы);
   - `git add <свои файлы>`;
   - `git commit` (conventional, тело на русском, подпись Co-Authored-By исполнителя);
   - `git show --stat HEAD`;
   - `git push origin codex/stage-18-editable-areas`;
   - `git push origin codex/stage-18-editable-areas:main`;
   - `gh run list --limit 3` → `gh run watch <id> --exit-status` (красная сборка — чинить сейчас);
   - если менялся код — `tools/ai/publish-local-r2r.ps1` при закрытом Map.
10. **Отчёт этапа** (раздел G протокола):
    - таблица G1 по пунктам A1…F8;
    - статусы G2;
    - `## ИТОГИ` (Сделано / Что дальше / Реализация проекта: N%);
    - первой строкой отчёта: `✅ Этап N/44 — R## готов. Завершено: K из 44. Следующий: R## <название>.`
11. **Сразу переходи к следующему этапу** (шаг 1), не дожидаясь подтверждения. Останавливайся только:
    - когда закончились выполнимые этапы (остальные ждут владельца);
    - при стоп-условии без обходного пути;
    - при нехватке контекста (см. §5).

## 6. Жёсткие правила продукта

- Офлайн, без подписки, без аккаунтов, **без генеративного ИИ** (ни арта, ни текста в продукте).
- Арт — только материалы владельца или процедурные заглушки исполнителя. Ничего из Inkarnate, игр и чужих паков. Provenance в `docs/09`.
- Категории карт не смешиваются (DEC-047). Новая мастерская — новая категория по шаблону DEC-047/048.
- Дефолты UI, раскладка клавиш, палитра, иконки, звук меняются только с решения владельца.
- Новый NuGet-пакет или программа — только с решения владельца (вопрос одним списком, см. §4.4).
- Stage 21/22 (подземелья) — только в R36/R37 и только после прямого «да» владельца.
- `reset`, `restore`, `stash` запрещены. Чужие незакоммиченные изменения не трогать.
- Отчёты владельцу — по-русски, простым языком, коротко. Сначала результат, потом детали.
