# Map в Claude: выбор модели и продолжение

Подготовлено по поручению владельца 2026-09-07. Это рабочие инструкции и инструменты разработки,
не новый функциональный этап. Общие требования остаются в [AGENTS.md](../../AGENTS.md).
Текущая продуктовая папка, ветка, HEAD и незавершённая работа — в верхнем
[STATE_HANDOFF.md](../STATE_HANDOFF.md). Комплект не закрывает визуальный остаток Stage 18.

## Как получить промпт одним сообщением

Скажи Codex или Claude: «Промпт для Fable» или «Промпт для Opus».
Без нового номера берётся продолжение текущей работы из handoff. «Промпт для Opus, этап 19»
подготавливает поручение по рекам. Подготовка и выполнение поручения различаются.
Генератор сам не запускает Claude, не выбирает модель, не пишет файлы и не начинает этап.

```powershell
pwsh -File tools/ai/New-ClaudeTask.ps1 -Model Fable
pwsh -File tools/ai/New-ClaudeTask.ps1 -Model Opus -Stage 19
pwsh -File tools/ai/New-ClaudeTask.ps1 -Model Fable -Task 'Исправь конкретное поведение, описанное владельцем.'
```

На этом ПК `pwsh` (PowerShell 7) не установлен: те же скрипты запускаются встроенным
`powershell -NoProfile -ExecutionPolicy Bypass -File ...` (Windows PowerShell 5.1). Для этого файлы
имеют UTF-8 BOM и не используют `$PSScriptRoot` в параметрах по умолчанию (2026-09-07).

Ассистент читает полученный текст, учитывает последние уточнения и отдаёт готовый промпт.
Параметр `-ProjectRoot` необязателен: помощники находят корень по собственному расположению,
поэтому работа из другой текущей папки не направит их в старый checkout.

## Модели

Имена и IDs подтверждены по [официальному списку моделей](https://platform.claude.com/docs/en/models/overview).
Машинный источник профилей — [claude-models.json](claude-models.json); не дублируй IDs в настройках проекта.

| Выбор | Профиль Map | Что меняется в постановке задачи |
|---|---|---|
| Opus | Claude Opus 5 | Конкретный результат, небольшой план, инварианты и связный проход через подсистемы |
| Fable | Claude Fable 5.1 | Цель всего порученного этапа, наблюдаемые критерии и свобода выбрать способ исследования/реализации |

Anthropic описывает Fable 5.1 как модель для длительных сложных задач и рекомендует задавать
результат без лишнего управления каждым шагом. Opus 5 позиционируется для сложной разработки.
Это заявления поставщика; сравнения моделей на самой Map пока не проводились.
Наш выбор подачи задачи — **PROPOSED**, а не измеренное преимущество.
Источники: [Fable 5.1](https://www.anthropic.com/claude-fable-and-mythos-5-1),
[Opus 5](https://www.anthropic.com/news/claude-opus-5),
[рекомендации Claude Code](https://code.claude.com/docs/en/model-config#work-with-fable).

Для сложной правки предложен `high`, без принудительного максимального расхода на каждую задачу.
Фактический режим выбирается в интерфейсе Claude. В установленном здесь Claude Code 2.1.263
доступны параметры `--model` и `--effort`; версия выше документированных минимумов для обеих моделей.
Доступ модели в аккаунте и её качество на Map этим не проверены. Сверяй выбранную модель по
интерфейсу/статусу: промпт не является доказательством runtime, aliases и fallback могут его менять.
Не заменяй Fable или Opus другой моделью молча.

Основной подготовленный путь — **локальный Claude Code**, который уже установлен на ПК.
Если владелец работает в обычном чате Claude, эти локальные файлы сами в него не попадают:
нужно передать промпт и относящиеся файлы; наличие модели не даёт чату доступ к Windows-проекту.
Не обещай выполнение нативных проверок в среде, где нет файлов, .NET и собственного окна.

## Что исправляют проектные навыки

Это меры против наблюдавшихся проблем работы над Map, а не утверждения о врождённых дефектах моделей.

| Риск | Что добавлено |
|---|---|
| Работа в старом checkout или потеря правок | Live root/branch/HEAD/dirty paths в `Get-MapContext.ps1` и промпте |
| Остановка на плане, готовая логика без кнопки | `map-local-feature`: сценарий от ввода до сохранённого результата |
| Перестройка целой карты ради одного стыка | `map-linked-geometry`: зависимости, устойчивые ID и локальный delta |
| Зелёные тесты при плохом рисунке | `map-visual-compare`: настоящий холст рядом с образцом и конкретные расхождения |
| Избыточные проверки и трата контекста | Короткий CLAUDE.md, выборочные skills, конечный объём проверок из AGENTS |
| Выдуманные API или перенос команд Codex | Официальная справка, проверка реальных инструментов и версий пакетов |
| Завышенная готовность | Отдельные статусы функции/внешнего вида и оценка всей актуальной roadmap |

Навыки лежат в `.claude/skills/`; каталог введён впервые, поэтому уже открытой сессии Claude Code
может потребоваться перезапуск для обнаружения. Проверка списка внутри Claude: `/skills`.
Достаточно подключать нужный навык по смыслу, все четыре сразу читать не требуется.
Формат и обнаружение: [Claude Code skills](https://code.claude.com/docs/en/skills).

## Инструменты

| Инструмент | Реальное назначение и состояние |
|---|---|
| `tools/ai/Get-MapContext.ps1 -AsJson` | Только читает Git, актуальный handoff и доступность локальных команд |
| `tools/ai/New-ClaudeTask.ps1 -Model Fable` | Печатает промпт из live context и выбранного профиля |
| `tools/ai/Get-RepositoryStatus.ps1 -AsJson` | Один проход публичного GitHub API по сохранённым кандидатам; не устанавливает пакеты |
| `tools/ai/Test-ClaudeSetup.ps1` | Проверяет локальные файлы, структуру профилей/навыков и конфигурацию |
| Microsoft Learn MCP | Настроен в корневом `.mcp.json`: поиск документации, чтение страниц и примеров .NET |
| Имеющийся `Map.Performance` | Адресные native helpers; режим выбирается по его README и изменённой функции |

Microsoft Learn отвечает без API-ключа; проверены initialize, список трёх инструментов и поиск
документации. Ответ поиска может относиться к другой версии API: сверяй TargetFramework и
PackageReference Map. В Claude Code `mcp get microsoft-learn` распознаёт project-конфигурацию
и пока показывает `Pending approval`. При первом подключении
Claude может показать своё согласие на project MCP: это механизм доверия Claude Code,
а не добавленный нами блокировщик. Конфигурация не меняет разрешения и глобальные настройки.
Справочник получает запрос по документации; не отправляй ему содержимое карты или приватные данные.
При недоступности используй официальные страницы и локальный код; сборка Map от MCP не зависит.
Источник: [MicrosoftDocs/mcp](https://github.com/MicrosoftDocs/mcp).

Context7 и Serena оставлены опциями, без установки. Первый в текущем README требует ключ,
второй добавляет язык-сервер и индексирование: их польза должна оправдать настройку и память.
Блокирующие hooks, автоматическое изменение разрешений и фоновая оркестрация не добавлены.

## Проверка комплекта и обновление

```powershell
pwsh -File tools/ai/Test-ClaudeSetup.ps1
pwsh -File tools/ai/Get-RepositoryStatus.ps1 -AsJson
```

Первая команда офлайн. Вторая обращается к GitHub один раз по каждому репозиторию; сетевой отказ
отмечает как `UNAVAILABLE`, не считает репозиторий проверенным. Дата push не доказывает качество,
а `NOASSERTION`/пустая лицензия требуют чтения лицензионного файла, не означают отсутствие лицензии.
Регулярная автоматическая проверка не настроена: исследование выполнено как разовый текущий срез.

При смене версии модели обновляй только профиль после проверки официальных сведений и прогони
генератор. Не копируй целиком чужие наборы инструкций. Исследование, даты, лицензии и решения
по следующим этапам находятся в [подборке](RESEARCH_AND_REPOSITORIES.md).
