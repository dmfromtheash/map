# Stage 20: дороги — исследование и художественные ориентиры

Дата проверки: **8 сентября 2026 года**. Этот комплект подготовлен по прямому запросу владельца для Claude Fable 5.1. Реализация Stage 20 здесь не выполнялась.

Исполняемое поручение: [STAGE_20_FABLE_PROMPT.md](../STAGE_20_FABLE_PROMPT.md).
Картинки лежат в [references](references/); список размеров, происхождения и SHA-256 — [REFERENCES.csv](REFERENCES.csv).

## Вывод для Map

По выбранным открытым источникам **Other World Mapper — самый полезный ориентир для связанных дорожных развилок**. DungeonFog полезен для оформления путей и окончаний, Dungeondraft — для редактируемой линии и порядка её наложения. Это оценка пригодности конкретных возможностей для Stage 20, а не рейтинг всех редакторов или доказанное превосходство их производительности.

По художественной задаче главнее **U1–U4 владельца**, дополненные Map Effects и 2-Minute Tabletop. Нужны собственные управляемые контуры, плавное раскрытие развилок, разные обочины и направленные детали. Богатая текстура на одинаковой полосе не решает задачу.

По реализации сначала использовать имеющиеся **SkiaSharp 3.119.4 и код Map**. Clipper2 — резерв для сложного offset/Union; perfect-freehand и Azgaar — источники отдельных идей. Готовой библиотеки, закрывающей одновременно редактируемый граф, художественные стыки, маски, уровни, Undo и сохранение Map, в исследованном наборе нет.

- Текущая Map: прочитаны roadmap, handoff, решения и относящийся код; подтверждены рабочая папка, HEAD и установленная версия SkiaSharp. Свежие сборка и тесты в этой подготовке не запускались: код не менялся.

- Репозитории: прочитаны указанные исходники и лицензии; проекты не устанавливались и не запускались. Ссылки на код закреплены на просмотренных коммитах.

### R1. SkiaSharp — основной инструмент, уже установлен

[Просмотренный SKPath.cs](https://github.com/mono/SkiaSharp/blob/11ec0df0cc6b03042ef78e06302c76802cfe972c/binding/SkiaSharp/SKPath.cs) подтверждает Boolean `Op` и `Simplify`; их неуспех нужно обрабатывать. [SKPathMeasure.cs](https://github.com/mono/SkiaSharp/blob/11ec0df0cc6b03042ef78e06302c76802cfe972c/binding/SkiaSharp/SKPathMeasure.cs) даёт положение и касательную по расстоянию; [SKPaint.cs](https://github.com/mono/SkiaSharp/blob/11ec0df0cc6b03042ef78e06302c76802cfe972c/binding/SkiaSharp/SKPaint.cs) — `GetFillPath`. Полезны для общей поверхности и направленных деталей дороги.

[MIT bindings](https://github.com/mono/SkiaSharp/blob/11ec0df0cc6b03042ef78e06302c76802cfe972c/LICENSE.md). Просмотренный upstream HEAD — `11ec0df0…`; это **не установленная версия Map**. Map использует **3.119.4**: проверять доступность конкретных API по этой версии и локальному коду. Существующие notices нативных компонентов сохраняются.

### R2. Clipper2 — резерв для контуров переменной ширины

Автор Angus Johnson, C#; просмотренный HEAD `f9c5eb6e…`.
В [Clipper.Offset.cs](https://github.com/AngusJohnson/Clipper2/blob/f9c5eb6e14a59f6f5d65fbfb3564519a561cf4fd/CSharp/Clipper2Lib/Clipper.Offset.cs) действительно есть `DeltaCallback64` и `Execute(callback, solution)`: смещение можно менять при обработке вершин. Поддерживаются виды соединений/окончаний и ограничение острых выступов. После offset выполняется Union-очистка.

[Документация offset](https://www.angusj.com/clipper2/Docs/Units/Clipper.Offset/Classes/ClipperOffset/_Body.htm) требует устранять пересечения закрытых контуров до расширения и обращает внимание на слишком короткие сегменты. Кривые предварительно дискретизируются. [Overview](https://www.angusj.com/clipper2/Docs/Overview.htm) объясняет внутреннюю целочисленную геометрию: масштаб точности должен быть привязан к документу, не к экрану.

[Boost Software License 1.0](https://github.com/AngusJohnson/Clipper2/blob/f9c5eb6e14a59f6f5d65fbfb3564519a561cf4fd/LICENSE).
[README](https://github.com/AngusJohnson/Clipper2) на дату проверки предупреждает о дефектах нового triangulation. Boolean/offset — отдельные подсистемы; новый triangulation для этой задачи не рекомендуем.

### R5. Авторская работа о плавности Catmull–Rom

Cem Yuksel, Scott Schaefer, John Keyser, **Parameterization and Applications of Catmull–Rom Curves**, Computer Aided Design 43(7), 2011.
[Страница авторов, формулы, иллюстрации и статья](https://www.cemyuksel.com/research/catmullrom_param/).

Центростремительная параметризация `alpha=0.5` исключает cusp и самопересечение **внутри отдельного кубического сегмента** в рассматриваемом семействе. Это полезный вариант для неравномерно расставленных точек. Он не гарантирует отсутствие пересечения разных сегментов, всей сети или расширенного неровного контура. Выбор alpha не закрывает автоматически задачу гладкой развилки.

## Инженерные выводы для текущей Map

Следующие пункты — предлагаемые правила Stage 20, а не результаты выполнения этапа.

1. **Связность и рисунок разделяются.** Документ хранит стабильные узлы и ветви, участок знает собственный профиль/стиль; изображение строится производно. Union соседних пятен без общей редактируемой связи не решает задачу.
2. **Дорога отличается от реки.** Допустимы циклы, нет течения и обязательного роста ширины, обочина не является речным обрывом. `CutsLand` не переносится.
3. **Общая граница строится после соединения.** Для связанных совместимых участков сначала строится поверхность узла, затем внешний контур, обочина и детали. Острый угол и разная ширина требуют обработки формы; один Union сам по себе не обещает художественного сглаживания.
4. **Штрих следует форме.** Детали располагаются по длине и касательной, обрезаются общим покрытием, затихают в узле. Рисование каждого участка отдельной толстой обводкой создаст внутренние заглушки.
5. **Неровность имеет предел.** Низкочастотная вариация каждой стороны добавляется к гладкой оси; амплитуда ограничивается шириной/кривизной. Точность дискретизации, художественная неровность и экранный антиалиасинг — разные параметры.
6. **Слои входят в сам проход рельефа.** Сейчас `SceneRenderer.DrawTerrain` рисует Землю и воду по уровням, а обычные объекты идут позже. Новая дорога в последнем проходе объектов окажется ошибочно поверх верхнего плато. Дороги нужно включить в согласованное упорядочение с Землёй/водой, используя общие эффекты владельца.
7. **Порядок на равном уровне явный.** Между владельцами действует порядок слоёв. Внутри одного владельца нужен сохраняемый порядок дороги/воды, согласованный с интерфейсом; нельзя спрятать произвольное правило «вода всегда последняя». Старые карты должны выглядеть как прежде.
8. **Граница с другим стилем не равна разрыву.** Геометрическая связь сохраняется, цвета могут различаться; не объединять стиль A/B/A ценой перестановки объектов и не стирать край через скрытую маской соседнюю дорогу.
9. **Сохранение и производительность не откладываются.** Preview вне истории; точные Undo/Redo; новая схема только при необходимых данных, старые схемы читаются; локальные изменения сохраняют независимые части, bounds учитывают обочины и экспортный запас.
10. **Графику проверяют в Map.** Настоящий холст/экспорт рядом с U1–U4, сначала без текстур. Зелёный тест геометрии не является художественным одобрением.

## Карта покрытия поручения

| Потребность владельца | Основание | Где закреплено в промпте |
|---|---|---|
| Полностью реализовать Stage 20 | Текущая roadmap и живой HEAD | Поручение, пользовательский результат, завершение |
| Редактируемые согласованные развилки | C1, R4, собственная модель Stage 19 | Общие узлы, разделение/отсоединение, локальное изменение |
| Качество как в присланных картах | U1–U4, E1–E4 | Три пресета, критерии краёв, ширины, колеи и узла |
| Красивая база без текстур | U3/U4, пара E2/E3, M1/M2 | Явная обязательная визуальная проверка без текстур |
| Правильная работа с Землёй и реками | TerrainOrder / DrawTerrain, текущие маски и уровни | Таблица порядка и запрет вырезания Земли дорогой |
| Полезные открытые решения | R1–R5, лицензии и ограничения | Сначала существующий стек, дополнительная библиотека по доказанной необходимости |
| Возможность передать без вложений | Устойчивые локальные файлы, хеши копий | Чтение изображений из references через Claude Code |

Техническая приёмка будущей реализации: адресные проверки связи/истории/round-trip, экспорт через тайл, один Release build, один собственный нативный сценарий. Художественная: общий вид и крупный план настоящей Map без текстур, устранение заметных швов и неестественных углов. Решение владельца о внешнем виде остаётся отдельным.
