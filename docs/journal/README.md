# Журнал Map

История проекта: что делалось, что не получилось, какие слова и решения владельца. Один файл на
месяц (`2026-10.md`), новые записи — **сверху**. Старые записи не правятся.

Текущее состояние — не здесь, а в `docs/STATE.md`. Почему сделано так — `docs/DECISIONS.md`.
Архив до 2026-09-08 — `docs/archive/docs/STATE_HANDOFF_BEFORE_20260908_CLEANUP.md`.

## Когда открывать журнал

Обычной сессии хватает `docs/STATE.md`. Журнал читается только когда:

1. задача продолжает прошлую работу — найти последнюю запись по теме (`rg "<тема>" docs/journal`);
2. что-то сломалось и нужно понять, когда и почему;
3. карточка или владелец ссылаются на запись («см. журнал 22.10»);
4. владелец спрашивает «что мы делали с …».

Читать точечно: найденную запись и соседние, а не весь месяц.

## Запись в конце этапа (обязательно, 5–15 строк)

```
## 2026-10-23 · <тема этапа> · <исполнитель: Claude / Sol / Astra>

**Поручение:** «<слова владельца одной строкой>»
**Сделано:** <что и где: файлы, классы, имена контролов>
**Проверено:** <сборка, тесты N/N, смоук, CI-run>
**Не проверено / не получилось:** <честно; всегда «живой просмотр владельцем», если его не было>
**Важно дальше:** <подводные камни, отвергнутые варианты, слова владельца>
**Коммиты:** <хеши>
```

Статусы `FACT` / `PARTIAL` / `NOT CHECKED` / `ASSUMPTION` — по `AGENTS.md`.
После записи — переписать `docs/STATE.md`, если что-то из него изменилось.
