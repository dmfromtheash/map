# CODEX.md — короткий рабочий вход

Map разрабатывается только для владельца и его текущего Windows x64 ПК. Главные правила находятся
в `AGENTS.md`; отдельной многоступенчатой acceptance-системы больше нет. Для передачи разовой
задачи использовать `docs/ai/PROMPT_CODEX.md`, не копируя туда постоянные правила и статические
списки инструментов.

## Перед работой

1. Прочитать `AGENTS.md` и `docs/STATE_HANDOFF.md`.
2. Открыть только относящиеся к задаче разделы спецификации, roadmap и `docs/DECISIONS.md`.
3. Проверить branch, `HEAD`, `git status`, `git log --all` и сохранить пользовательские изменения.
4. Сопоставить текущий checkout с `Последним продуктовым HEAD` из handoff. Новый stage нельзя
   начинать от более старого commit только потому, что эта папка уже открыта.

## Обычный цикл

1. Сформулировать один практический результат.
2. Внести минимальное изменение.
3. Один раз собрать production solution.
4. При необходимости запустить один адресный тест или один локальный UI smoke.
5. Сообщить результат и остаточный риск простым языком и закончить обязательным разделом
   `ИТОГИ` по формату из `AGENTS.md`.

Не создавать отдельные stage-prompts, review-пакеты, evidence-деревья и новые worktree ради
обычной проверки. Не запускать все тесты и каталоги инструментов «для уверенности».

Один короткий исполняемый контракт активного этапа допустим, когда владелец прямо его просит.
Каждый новый исполняемый prompt обязан явно потребовать итоговый отчёт по формату `AGENTS.md`,
включая простые формулировки, следующий шаг и подтверждённую оценку запрошенной готовности.
Техническую оценку, непроверенный остаток и отложенный художественный контент разделять.
Stage-контракты в `docs/STAGE_*.md` являются историческими документами реализованных этапов.
Stages 12A–17 находятся в линейной продуктовой истории. Точный текущий рабочий каталог, branch,
`HEAD` и незакоммиченное состояние записываются только в `docs/STATE_HANDOFF.md`.
Stage 17 реализован по отдельному поручению владельца; будущие этапы автоматически не начинать.
Текущие исправления, проверенные сценарии и
остаточные ограничения записаны в handoff; наличие offline P0/P1 не означает полной технической
готовности. Владелец 2026-09-03 отдельно разрешил commit и push текущего накопленного
результата; разрешение исполнено для `codex/stage-16-final-offline-parity`. Для будущих remote-
действий снова требуется новое прямое разрешение.

## Локальные команды

```powershell
dotnet build .\Map.slnx -c Release
dotnet run --project .\src\Map.App\Map.App.csproj -c Release
```

Адресный тест запускается напрямую по нужному `.csproj` и, когда возможно, с `--filter`.

VM, installer, portable/release-пакет, другой ПК и публикация не входят в обычный цикл и требуют
нового прямого запроса владельца.
